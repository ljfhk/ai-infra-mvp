# AI Infra 能力看板 · 落地计划

> 背景：把 JD 里常见的 9 个 AI Infra 技术点（推理部署 / 容器版本 / OpenAI API / 鉴权限流 / 性能评测 / 量化 / 故障排查 / 脚本交付 / 文档复盘），从「脚本 + 命令行」升级为「服务器巡检系统页面上可操作、可展示」的能力。
> 目标：① 自己日常用；② 作为面试 / 交付 demo，证明这 9 项不是停留在简历上。
> 配套文档：`推理网关部署选型速查表.md`（网关架构选型）、`推理网关实现文档.md`（档1 网关已实现细节）。本文档讲「把 JD 能力挂到页面」的整体方案。

---

## 一、核心原则

| 原则 | 说明 |
|------|------|
| **已落地 → 接入口** | 网关、推理接口已经做完，页面给入口和状态，不重复造。 |
| **可操作 → 做交互** | 启停、压测、脚本执行、诊断这类，做成按钮/表单。 |
| **危险 → 只展示** | Docker/CUDA 版本**升级**是系统级操作，页面只读 + 文档入口，绝不开放点击升级。 |
| **重活 → 任务化** | 量化、压测会下载大模型 / 打高负载，必须异步任务 + 进度 + 离线优先，不阻塞 UI。 |
| **不撑爆导航** | 9 项能力不做 9 个一级 tab，统一收进一个「AI Infra 能力看板」单页。 |

## 三、九项能力 → 页面落地映射

### 1. 推理平台部署（vLLM / SGLang）— P0
- **现有基础**：`InferenceService` 已实现 `/api/inference/{status,models,metrics,restart}`，`index_v5.html` 已有「推理服务管理」tab。
- **页面模块**：平台切换下拉（vLLM / SGLang）、启动 / 停止 / 重启按钮、模型加载状态。
- **后端扩展**：`InferenceService` 增加 `platform` 字段；`application.yml` 的 `inference.restart.command` 支持按平台区分；状态轮询复用 `?baseUrl=`。
- **操作深度**：全操作。

### 2. Docker / CUDA / Container Toolkit 版本管理 — P1（只读）
- **页面模块**：「环境信息」卡片展示 `docker version`、`nvidia-smi -L`、`nvcc --version`（或 `nvidia-smi` 里的 CUDA Version）。
- **后端新增**：`EnvService.environment()` 在目标机执行上述命令，返回结构化 JSON。
- **操作深度**：**只读**。版本升级是系统级操作，页面只展示 + 文档入口，不开放升级按钮。

### 3. OpenAI 兼容 API 服务 — P0（已落地）
- **现有基础**：网关 `/api/gateway/v1/chat/completions`、`/v1/models` 已提供 OpenAI 兼容代理。
- **页面模块**：网关控制台「测试请求」可直接对话；文档说明 Base URL 用法。

### 4. 鉴权 / 限流 / 并发控制 — P0（半落地 → 全操作）
- **现有基础**：网关控制台已有 Key 管理、全局 QPS、模型路由。
- **扩展**：补**全局最大并发**（当前只有 QPS/秒）。`GatewayService` 加 `Semaphore` 计数，`gateway_config` 加 `global_concurrency`；`allow()` 之后校验并发；前端「限流配置」加「最大并发」输入框。
- **操作深度**：全操作。

### 5. 推理性能评测（TTFT / TPOT / 吞吐 / 显存）— P1
- **页面模块**：「压测台」表单（模型 / 并发数 / 请求数 / prompt 长度 / 时长）→ 结果指标卡 + 折线图（Chart.js，复用现有前端栈）。
- **后端新增**：`BenchmarkService`。入参 `{model, concurrency, requests, promptLen, baseUrl}`。
  - **TTFT 测量必须走 `stream:true`**，但网关当前强制 `stream:false`——因此评测**直连 vLLM**（或新增一个支持流式的评测代理），按 SSE 首 token 时间算 TTFT，按 token 间隔算 TPOT，按总量/总时算吞吐。
  - 显存占用从 vLLM `/metrics` 的 `kv_cache_usage_perc` / 进程内存聚合。
  - 结果存 `benchmark_run` 表，前端轮询或结果回调。
- **注意**：优先用后端线程池自发包（避免目标机额外装 locust）；压测默认低并发、设上限，防止单卡 vLLM 被打 OOM。
- **操作深度**：全操作。

### 6. 量化方案（FP16 / BF16 / AWQ / GPTQ）— P2（资源敏感）
- **页面模块**：「模型量化」任务页：选基座模型 + 量化方式（AWQ/GPTQ/INT4）+ 输出路径 → 提交异步任务 → 进度条/日志轮询。
- **后端新增**：`QuantizeService`。提交任务写 `quantize_task` 表（status / log_path / progress）；后台触发 Python 量化脚本（`llm-compressor` / `auto-gptq`）。
- **⚠️ 流量敏感红线**：量化会下载大模型 + 吃显存/磁盘。必须：① 先查本地缓存（`~/.cache/huggingface/hub` / ModelScope）；② 任务化、离线可跑；③ 进度可视化、可取消。
- **操作深度**：全操作（异步）。

### 7. OOM / CUDA 报错 / API 超时排查 — P1
- **页面模块**：「诊断助手」：聚合 vLLM 日志 + 正则匹配常见错误（OOM / CUDA error / timeout / context length）→ 返回 `{level, pattern, suggestion}` 列表。
- **后端新增**：`DiagnoseService`。读目标机 vLLM 日志（tail）+ 可主动跑 `nvidia-smi`、`dmesg | grep -i cuda`；结果结构化返回。
- **操作深度**：半操作（看结果 + 建议，保留「去服务器确认」提示）。

### 8. Shell / Python 脚本交付 — P1
- **页面模块**：「脚本执行台」：把工作区里的 `_*.py`、`verify_gw.sh` 等脚本目录化 → 选脚本 + 填参数 + 选目标主机 → 执行 → 看输出。
- **后端新增**：`ScriptService`。扫描指定目录脚本 → 列出 → 经 SSH 在目标机执行 → 返回输出（流式或轮询）。可复用现有 `_ssh_*.py` 思路。
- **⚠️ 安全**：目标主机 + 命令需白名单 / 参数校验，防命令注入。
- **操作深度**：全操作。

### 9. 部署文档 / API 手册 / 故障复盘 — P2
- **页面模块**：「知识库」：索引工作区 `.md` / `.html` + 公众号文章链接 → 列表（标题 / 类型 / 路径）→ 点击打开。
- **后端新增**：`DocService`（或纯静态索引）扫描产出清单。
- **操作深度**：只读（链接聚合）。

## 六、落地顺序与工作量

| 批次 | 模块 | 工作量 | 说明 |
|------|------|------|------|
| **P0** | 并发控制 | 小 | 网关加 Semaphore + 配置项，半天上。 |
| **P0** | 推理平台切换 | 中 | 扩展 InferenceService + 前端下拉/按钮。 |
| **P1** | 脚本执行台 | 中 | 复用 SSH 思路，最有"交付"说服力。 |
| **P1** | 压测台 | 中 | 直连 vLLM 测 TTFT/TPOT，面试可演示。 |
| **P1** | 诊断助手 | 中 | 日志正则 + 建议，补全 SRE 定位能力。 |
| **P1** | 环境信息（只读） | 小 | 执行命令返回 JSON，纯展示。 |
| **P2** | 量化任务页 | 大 | 资源敏感，放最后，必须异步+离线优先。 |
| **P2** | 知识库 | 小 | 链接聚合，把已有文档串起来。 |

**建议先做 P0 + P1 的「脚本执行台 + 压测台 + 诊断助手」**——这三项最像 SRE / AI Infra 日常，面试最好讲，且风险低、不碰大模型下载。

## 七、风险与注意（红线）

- **量化 / 压测**会触发大模型下载或高负载，严格执行：先查本地缓存、任务化、离线优先、设并发/资源上限。你的网络流量敏感，别让页面偷偷拉十几 GB 权重。
- **Docker / CUDA 升级**禁止页面操作（系统级、易搞挂环境），只展示版本 + 文档。
- **脚本执行**走 SSH 必须参数校验 / 命令白名单，防注入；建议只允许工作区内已知脚本 + 受限参数。
- **压测**默认低并发、可配上限，避免单卡 vLLM 被打 OOM。
- 沿用既有外部 `web-static/` 托管：前端改动只换文件、不重打 jar，避免误伤其它页面。

## 八、与现有系统的关系

- 复用 `/api/inference/*`（推理状态/指标）、`/api/gateway/*`（鉴权限流路由）。
- 复用 SQLite 持久化、外部静态目录托管、现有 vLLM 地址配置。
- 新模块均为现有单 jar 内新增 Service + Controller，保持「档1 嵌入式单体」形态，不引入新进程。
