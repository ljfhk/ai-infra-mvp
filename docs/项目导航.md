## 一、一句话定位

这是一个 **AI Infra 故障诊断与记忆引擎** 的最小可用产品（MVP）：

- 用诊断脚本 + 本地 LLM（Qwen via vLLM）做服务器 / AI 基础设施故障的「诊断 → 建议 → 人审 → 执行」闭环；
- 带一层轻量推理网关（鉴权 / 限流 / 路由），把 OpenAI 兼容请求转发给本地 vLLM；
- 记忆层记录历史故障，下次同类问题能召回参考；
- 通过 MCP / A2A 暴露集成协议（MCP 真实可用，A2A 演示态）。

## 三、建议阅读顺序（慢慢看，不一次全进脑子）

### 第一阶段：主干闭环（最重要，其他都是它的延伸）

1. `service/AgentLoopService.java` —— 状态机怎么流转
2. `service/InfraService.java` —— 诊断脚本怎么被调起来
3. `service/GatewayService.java` 里的 `internalChat` —— 怎么把请求丢给本地 Qwen
4. 前端 `static/index.html` 的「脚本交付 / 诊断」面板 —— 人审确认那一步在哪

### 第二阶段：记忆 + LLM 效果层

1. `service/MemoryService.java` —— 故障怎么被记住、下次怎么召回
2. `controller/LlmController.java` —— Prompt 模板 / 补全 / 结构化输出三个端点

### 第三阶段：集成与网关（可以最后看，不影响用）

1. `controller/AgentController.java` + `service/McpService.java` / `service/A2aService.java` —— MCP 真实、A2A 演示态
2. `service/GatewayService.java` 的鉴权 / 限流 / 路由 / 假成功降级
